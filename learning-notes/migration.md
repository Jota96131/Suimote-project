# マイグレーションとは

データベースの構造（テーブルやカラム）をコードで管理・変更する仕組み。

## たとえ

引っ越しの手順書のようなもの。

- 「本棚を置く」→ テーブルを作る
- 「本棚に仕切りを追加」→ カラムを追加する
- 「仕切りを外す」→ カラムを削除する

この手順書（マイグレーションファイル）を共有すれば、全員が同じDB構造を再現できる。

## Supabaseでの例

`supabase/migrations/` にSQLファイルとして保存される。

```sql
-- 20240101_create_profiles.sql
CREATE TABLE profiles (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id),
  display_name TEXT,
  area_id INT REFERENCES areas(id)
);
```

## なぜ直接DBをいじらないのか

| 直接変更 | マイグレーション |
|---|---|
| 誰がいつ何を変えたか不明 | Gitで履歴が残る |
| 他の人の環境で再現できない | コマンド1つで同じ構造にできる |
| 本番で適用漏れが起きる | 順番通りに適用される |

## 一言まとめ

DBの「設計図の変更履歴」。変更を1つずつファイルに書いておくことで、誰でも同じデータベースを再現できる仕組み。
