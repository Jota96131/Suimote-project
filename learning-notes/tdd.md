# TDD（Test-Driven Development / テスト駆動開発）とは

「テストを先に書いてからコードを書く」開発手法。Red → Green → Refactor の3ステップを繰り返す。

## たとえ

料理する前にレシピ（テスト）を書く。「カレーは甘口であること」と先に決めてから作り始める。味見（テスト実行）して合格したら、盛り付けをきれいにする（リファクタリング）。

## 具体例

```ts
// ① Red: 失敗するテストを先に書く
test('いいね数が1増える', () => {
  const count = addLike(0)
  expect(count).toBe(1)
})

// ② Green: テストが通る最小限のコードを書く
function addLike(current: number): number {
  return current + 1
}

// ③ Refactor: コードをきれいにする（今回は十分シンプルなのでそのまま）
```

## 3つのステップ

| ステップ | やること | 状態 |
|---|---|---|
| Red | 失敗するテストを書く | テスト❌ |
| Green | テストが通る最小限のコードを書く | テスト✅ |
| Refactor | コードを整理する | テスト✅のまま |

## なぜ使うのか

| 使わない場合 | 使う場合 |
|---|---|
| コードを書いた後にバグに気づく | 先にテストがあるのでバグを防げる |
| 何を作るか曖昧なまま進む | テストが仕様書になる |
| リファクタリングが怖い | テストがあるので安心して変更できる |

## 一言まとめ

「先にテストを書く → 通るコードを書く → きれいにする」を繰り返す開発手法。テストが安全ネットになるので、安心してコードを変更できる。
